
# 再保系統 - UI/UX 需求規格書

## 系統概述
- **系統名稱**：再保系統
- **主要功能模塊**：再保合約管理、額度管理、保費計算、理賠管理、對帳管理、報表分析、系統管理等
- **基礎框架**：已完成「再保合約管理 > 合約簽訂與維護 > 合約基本資訊管理」的 HTML mockup

## 設計規範

### 一、整體架構與導航

#### 1.1 頂部導航條
- **背景**：紫色漸層（`linear-gradient(135deg, #667eea 0%, #764ba2 100%)`）
- **系統名稱**：`📋 再保系統`（固定位置，左上角）
- **路徑導航**：麵包屑式路徑（`>`分隔）
  - 格式：`模塊名 > 子模塊名 > 功能名稱`
  - 例如：`再保合約管理 > 合約簽訂與維護 > 合約基本資訊管理`
- **字體顏色**：白色（opacity: 0.9）
- **尺寸**：系統名稱 18px，路徑 13px

#### 1.2 頁面標題區
- **背景**：白色
- **邊界**：下邊框 1px solid #e0e0e0
- **內容**：圖標 + 標題 + 操作按鈕
  - 圖標：28px emoji（如📑、📋、💰等）
  - 標題：24px bold，顏色 #333
  - 操作按鈕：通常為「❓ 幫助」
- **排列**：標題左對齊，按鈕右對齊，使用 flexbox

### 三、組件規範

#### 3.1 按鈕
```
基礎按鈕規格：
- 高度：12px padding (上下) × 16px padding (左右)
- 邊角：border-radius 6px
- 字體：13px bold，display inline-flex，gap 6px
- 過渡：transition all 0.3s ease
- Hover 效果：box-shadow 0 4px 12px rgba(...)

按鈕類型：
- btn-primary：綠色（#28a745）→ Hover #218838，用於「新增」、「保存」、「提交」、「續期」等
- btn-secondary：灰色（#6c757d）→ Hover #5a6268，用於「查詢」、「導出」等
- btn-info：藍色（#17a2b8）→ Hover #138496，用於「查看」、「編輯」等
- btn-warning：黃色（#ffc107），用於「編輯草稿」、「警告操作」
- btn-danger：紅色（#dc3545）→ Hover #c82333，用於「刪除」
```

#### 3.2 狀態標籤
```
- Padding：4px 12px
- Border-radius：20px
- Font-size：12px bold
- 顯示為 inline-block

狀態類型：
- 草稿（draft）：淺灰背景 #e2e3e5，文字 #383d41
- 簽核中（signing）：淺黃背景 #fff3cd，文字 #856404
- 生效中（active）：淺藍背景 #cce5ff，文字 #004085
- 已失效（expired）：淺青背景 #d1ecf1，文字 #0c5460
```

#### 3.3 版本標籤
```
- 背景：#667eea（紫色）
- 文字色：white
- Padding：2px 8px
- Border-radius：12px
- Font-size：11px bold
- 邊距：margin-left 8px
- 顯示為 inline-block

例：`CT-2024-FB-001` `V1`
```

#### 3.4 商品/風險標籤
```
- 背景：#e3f2fd（淺藍）
- 文字色：#1976d2（藍色）
- 規格同上（Padding 2px 8px，border-radius 12px，font-size 11px bold）

例：`火險(FB)`、`海險(MV)`
```

### 八、功能規範（以「合約基本資訊管理」為例）

#### 8.1 表格功能
- 新增、查看、編輯、刪除、續期等操作
- **狀態判定**：
  - 草稿 → 顯示編輯、刪除按鈕
  - 簽核中 → 顯示編輯、簽核狀態查詢按鈕
  - 生效中 → 顯示查看、版本按鈕；距失效30天內還顯示續期按鈕
  - 已失效 → 顯示查看、續期按鈕
- 支援進階查詢（可展開/隱藏查詢面板）

#### 8.2 新增/編輯流程
- 分為多個表單區段（①基本資訊、②險別/商品、③期間、④內部資訊等）
- 新增時全部欄位可編輯
- 編輯時根據狀態決定欄位是否唯讀
- 包含即時預覽區域（如編號預覽）
- 表單驗證即時顯示

#### 8.3 特殊功能
- **編號系統**：`CT-YYYY-XX-XXX`
  * CT = Contract
  * YYYY = 年份
  * XX = 險別代碼（FB=火險、MV=海險、AV=航空險、LB=責任險、HE=健康險、CA=車險(任意)）
  * XXX = 序號
- **險別選擇**：單選主要商品（決定編號），先不考慮複選
- **版本管理**：同一合約號碼可有多個版本（V1、V2...）
- **續期流程**：
  * 失效前30天內顯示續期按鈕
  * 已失效也顯示續期按鈕
  * 點擊續期生成新編號、預填資訊、進入簽核流程

## 生成其他章節頁面的指令

當使用此規格書生成其他章節（如「額度管理」、「保費計算」等）的 HTML mockup 時，應：

1. **保持設計一致性**
   - 使用相同的色彩系統、字體、按鈕樣式
   - 保留頂部導航和頁面標題結構
   - 遵循卡片、表單、表格的規範

2. **調整內容**
   - 修改系統路徑（麵包屑）
   - 修改頁面標題和圖標
   - 根據功能調整表格欄位、表單欄位、操作按鈕

3. **功能邏輯**
   - 根據各章節的業務流程設計操作流程
   - 設計相應的模態對話框（新增、編輯、查詢等）
   - 實現相應的驗證和提示機制

4. **範例適配**
   - 將「合約」替換為相應的業務對象（如「額度」、「費單」等）
   - 將「合約編號」替換為相應的編號（如「額度編號」等）
   - 將相應的狀態改為符合業務需求的狀態

## HTML 文件特性

- **框架**：純 HTML5 + CSS3 + Vanilla JavaScript
- **無第三方依賴**：不使用任何前端框架（如 React、Vue）
- **前端交互**：JavaScript 實現表單驗證、模態對話框、查詢篩選等
- **響應式**：支援桌面、平板、手機各種尺寸
- **文件位置**：`/mnt/data/1.1.1_合約基本信息錄入_Mockup_Updated.html`

---

此指令可直接複製給其他 AI 模型或開發人員，以生成符合設計規範的其他章節頁面。
